## 作者方法：先定义可信数据，再选择工具

文章重点不是“把内容转成文本”，而是让每条结果能回到来源、关系、处理过程与质量状态。下表为原文八步的压缩整理。

| 步骤 | 作者的方法与产物 | 原文强调的边界 |
| --- | --- | --- |
| 1. 业务数据规范 | 先明确用途、必填字段、关联关系、证据要求、人工复核门槛，形成数据字典 | 同素材发布 10 次，传播统计可保留 10 条；自然讨论分析可关联重复组，不先硬删 9 条。去重策略依赖分析口径 |
| 2. 原始层保留 | 保存原文、文件、链接、原始 ID、发表与采集时间；清洗文本、OCR、ASR、模型标签另存 | 不覆盖来源，以便复查、重跑与报告溯源；保留政策另见整理者补充，不能理解为无限期保存个人数据 |
| 3. 建立关系 | 用平台内 user_id、post_id、comment_id、parent_comment_id 连接用户、帖子、评论和回复；平台名与原始 ID 组合避免碰撞 | 昵称、头像相同不能认定跨平台同一人；缺少可靠主键及授权，不拼接个人轨迹 |
| 4. 多模态归一 | 文本清洗仍附证据原句；OCR 保留文字及位置，视觉识别对象和场景；ASR 附时间码，必要时分离说话人；视频按时间融合音轨与关键帧 | 先稀疏抽帧、转写，再对相关片段加密处理，不默认逐帧全量；抽帧漏检风险需另验 |
| 5. 冲突、重复与质量 | 冲突回查时间码或图像位置，核对单位、上下文、发布时间；关联重复组；相关性、重复性、质量异常分开处理 | 未解决冲突进入待核，不参与精确数值统计；高相似或高风险分只作排队依据，不自动删除 |
| 6. 结构化表达 | 区分表达者、评价对象、产品部件/属性、关系/事件、观点/问题/意图，并关联文字、图片位置或音频证据 | 不只给整句话一个情感标签；固定 JSON 字段、枚举及空值规则；复杂指代、多对象、多语、长文再考虑大模型，稳定高频规则可用规则或小模型 |
| 7. 验收与回归 | 用人工确认的正常样本和难例建立 golden set；规则或模型变化后重跑；检查来源完整、评论回链、媒体定位、冲突状态和标签对象 | 验收门槛、样本规模、覆盖要求未给出，不补造通用及格线 |
| 8. 分层版本入库 | 原始、处理、质量、版本分层；记录规则、模型、schema 版本，使结果可回查与重算 | 文末仅预告 Elasticsearch 查询下篇，没有可读续篇链接，不补写索引与查询实现 |

### 冲突证据等级：作者自定，不是行业标准

| 等级 | 原文定义的压缩转述 |
| --- | --- |
| A | 官方字段或人工确认 |
| B | 原始媒体可确认 |
| C | 多模型一致且上下文对齐 |
| D | 单模型结果 |
| E | 规则候选 |

作者要求保留原值、修正值、依据等级、修正原因、复核状态和模型版本。文中 ASR “100” 与 OCR “11000”的冲突例子没有给出单位和正确值，本卡不补全、不替作者裁决。

等级是作者组织复核的经验框架，并非准确率排序的验证结果。尤其“多模型一致”与“人工确认”仍有边界，见后文。

### 质量分流而不是一刀切删除

1. **正常数据**：进入后续结构化与验收。
2. **重复数据**：保留关联关系，按业务口径统计。
3. **低质量数据**：修复或隔离，明确状态。
4. **高风险数据**：进入人工复核队列。

活动统一素材也可能是正常传播。相似度和风险分不能单独证明垃圾、造假或应删除；保持判断依据，避免把清洗规则变成未经审查的业务结论。

## 作者的工具选型与交付清单

- 小批量先用 API 验证；高频、稳定任务再评估本地部署。不能只看单次价格，要用真实样本评估方言、噪声、中英混合、竖屏字幕、小字等条件。
- 建议工作台流程：输入 → 工具路由 → 原文与识别结果对照 → 人工修正 → JSON/CSV 导出。记录调用次数、耗时、费用与失败原因。
- 建议交付：**数据字典、关系说明、处理流程、质量报告、难例集、人工复核队列、版本记录**。
- 原文没有完整 schema、代码、权限方案，也没有本地迁移成本临界点。以上是作者设计经验，不是可直接部署的成品。

## 整理者补充：落地前必须明确的边界

以下不是作者原话，也不是已执行的项目结果。

1. **可追溯不等于无限期保留。** 需另外确定数据来源授权、目的、最小必要字段、访问权限、保留期限及删除流程；原文的原始层保留原则不应被当成无限期保存个人数据的政策。关系示意图含 email 字段，不因此扩大采集范围。
2. **模型一致不等于独立真值。** 多个模型可能共享偏差；人工确认也需标注规则、复核与争议处理。证据等级可作流程标签，不能直接换算为准确率。
3. **结构正确不等于事实正确。** JSON/schema 检查与对象指代、事实、证据支持应分开验收。无证据、抽取失败、原文不存在与待复核最好有不同状态；这是落地建议，原文未给完整状态定义。
4. **抽帧策略需要目标驱动验证。** 稀疏抽帧节省处理量，却可能漏掉短暂字幕或事件；应以任务样本比较漏检与成本，而非固定照抄频率。
5. **版本留档不自动实现可重现。** 建议同时明确输入快照、处理配置及重跑范围；模型或外部 API 变动可能影响复现。原文未交付这套实现。
6. **质量报告应反映未解决问题。** 建议分模态、来源、对象和错误类型报告，而非只列总成功率；重复关联、隔离和未决冲突也应可追踪。具体指标及阈值需由任务方定，不在这里伪造。

### 仍未说明，不能当成完整方案的部分

- 数据量与业务收益基准；人工 golden set 规模、标签一致性和数值验收阈值。
- 抽帧频率、相似度阈值、风险评分公式与置信度校准方法。
- 完整 schema、运行代码、权限与保留/删除方案。
- API 转本地的成本临界点、吞吐、延迟、故障恢复与部署测评。
