## 收集边界

- 收录可复用逻辑，包括不完整但值得继续补充的想法、交易结构、入场/退出条件、持有时间、仓位管理、估值推导。
- 不持久化单纯的临时点位、当天情绪或持仓表态。**用于解释方法的历史数字例子可以保留**，必须标明日期与历史案例属性，不变成当前买卖建议。
- 同一方法跨帖补充到同一 Markdown 卡片；新增方法再建卡。不为每条推文单独建文件。
- 没有可用新证据时不改文件；不能访问原帖时不假装已核验。不将置顶旧帖当新帖。
- 作者观点、被引用者的问题、整理者解释、独立核验结论分开写。作者自报收益不等于可复现的历史绩效。
- 用户手工摘录可作为来源线索；没有原帖链接时明确标注。不得编造日期、标的、单位、止损或遗漏规则。
- 不复制大量与研究无关的原文；优先概括，保留关键数字、逻辑、必要短引文及原帖链接。

## 每张方法卡的最小结构

1. 方法名称、作者/来源、适用对象、当前状态、最近更新日期
2. 用通俗语言解释的思考链条和工具机制
3. 原作者的前提、入场、工具/期限、仓位、持有、退出/失效条件；未说明的直接写“未说明”
4. 历史案例和必要计算，列清假设，不补成真实成交
5. 来源证据：原帖 ID/链接、原文显示时间与时区可信度、核验/收集日期
6. 版本差异、更正与待核验问题
7. 追加记录：新增来源究竟补了什么、与哪些旧规则有冲突

## 增量维护

先读现有卡片和来源列表，按原帖 ID/链接去重，再按“补充、明确更正、并列变体、存在冲突”更新。明确更正保留旧值与更正关系；不同日期、不同情境的规则不能自动合并成一套规则。更新同一张卡时同步维护来源和更新记录。

后续可以定期评估：保留、补证、合并重复内容、标记低价值或移除；目前不自动删除尚未验证的方法。Markdown 加 Git 历史足以支持现阶段追踪，暂不引入数据库或复杂格式。

只有日后另行决定研究时，才讨论参数冻结、可复现验证与 market-regime-lab 的采纳；此处不做交易、不部署、不产生自动执行信号。
