## 1. Softmax：指数归一化与数值稳定性

**作者来源：** [Softmax 展开帖](https://x.com/Zen_with_AI/status/2114772798204002673)。作者重点是沿指定轴归一化、先减最大值，以及批量输入的轴和维度保留。

### 输入、输出与机制

输入为实数数组及归一化轴；输出与输入同形状。对一个长度为 N 的切片：

`p_i = exp(x_i - m) / sum_j exp(x_j - m)`，其中 `m = max_j x_j`。

减去同一个常数不改变精确数学下的比例，但能避免直接对很大的正数求指数。最大值与求和都要沿同一轴，并保留用于广播的维度。最后一轴是常见接口选择，不是 Softmax 定义强制要求。

对非空、有限输入，结果非负，指定轴上的和在浮点误差内接近 1。它把分数归一化，并不自动使模型输出成为经过校准的概率。

### 复杂度与边界

- 长度 N 的切片时间 O(N)；保存输出和常见中间数组需要 O(N) 空间。批量输入按总元素数计。
- 减最大值处理的是溢出风险，不代表能接受任意 NaN、正无穷、全负无穷或空切片。接口需要明确拒绝还是采用特殊规则。
- 下溢到 0 不一定是错误；不要要求每项都严格大于 0。
- “直接 softmax 后取 log”可能丢失很小概率的信息；需要对数概率时，应进一步学习稳定的 log-softmax，而不是随意加常数改变分布。

**一手核验：** [SciPy softmax 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.special.softmax.html)说明指定轴归一化和通过平移避免溢出的实现方法。

**待练习：** 单向量与二维批量、不同 axis、输入整体加常数后结果近似不变、大幅值输入、行和、输出 shape；为非法输入写清契约。比较时使用容差，不要求浮点逐位相等。

## 2. Attention：先讲清维度，再讲多头

**作者来源：** [Attention 展开帖](https://x.com/Zen_with_AI/status/2114772798849913297)。作者展示缩放点积注意力、因果遮罩，以及投影、拆头、拼接和输出投影。

### 输入、输出与机制

单头定义：

`Attention(Q, K, V) = softmax(QK^T / sqrt(d_k) + mask) V`。

若 Q 为 `n_q × d_k`、K 为 `n_k × d_k`、V 为 `n_k × d_v`，分数矩阵为 `n_q × n_k`，输出为 `n_q × d_v`。Softmax 沿 key 维归一化。自注意力常有相同的序列长度；交叉注意力不能默认 query 和 key 一样长。

缩放的直觉是控制点积的量级。原论文中“点积方差随 d_k 增大”的说明依赖分量独立、零均值、单位方差等假设，不是对所有输入分布的无条件定理。

多头注意力使用不同的可学习 Q/K/V 投影，在各头中计算，再拼接并做输出投影。它不等于把原输入随便切几块。教学实现可先做无 batch 版本，但应说明与生产接口的差别。

### 复杂度与边界

- 自注意力的注意力混合部分约 O(n²d)，稠密输入/输出投影还包括 O(nd²)；不能将前者称为完整模块全部开销。
- 显式保存全部头的权重时，权重空间为 O(hn²)，另有 Q/K/V 和输出。这里描述常规教学实现，不是优化内核的显存上界。
- 检查 h 为正整数、模型维度能否整除头数、Q/K/V 维度、mask 的形状与广播。
- mask 的布尔含义因 API 不同而异。原示例 True 表示可见；不能未经核对复制到 True 表示屏蔽的接口。

**原示例的静态审查：** 将被遮罩分数替成 -1e9 时，如果一行全部被遮罩，该行成为相等的有限值，稳定 Softmax 会给出均匀分布，而不是“没有注意力”。这由公式推导得出，本次未运行代码。需要拒绝全屏蔽行，或明确约定其输出及实现方式；只把常数换成负无穷仍需处理全屏蔽行。-1e9 也不是任意 dtype 的通用安全常量。

**一手核验：**
- [Attention Is All You Need §3.2](https://arxiv.org/html/1706.03762)：缩放点积与多头投影。
- [PyTorch 2.14 scaled_dot_product_attention](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.scaled_dot_product_attention.html)：SDPA 布尔 mask 中 True 参与注意力，并提示它与 MultiheadAttention 的 key_padding_mask 语义不同。

**待练习：** 先手算极小矩阵，检查每个维度；验证因果遮罩下改变未来位置不影响过去位置输出；覆盖全屏蔽行、跨长度注意力与非法头数。和框架对拍时统一权重、dtype、mask、dropout 与容差，不把接口差异误判为算法错误。

## 3. K-Means：交替优化、初始化与停止时的一致性

**作者来源：** [K-Means 展开帖](https://x.com/Zen_with_AI/status/2114772799487369429)。作者介绍最近中心分配、均值更新、初始化与多次尝试、空簇处理和特征尺度。

### 输入、输出与机制

输入为 `n × d` 数据矩阵、簇数 k、初始化和停止参数；输出通常包括 k 个中心及每个样本的标签。目标是减小样本到其所属中心的平方欧氏距离之和。

Lloyd 迭代的两步是：固定中心，将每个样本分给最近中心；固定分配，用簇内样本均值更新中心。重复到满足停止条件或达到迭代上限。它依赖初始化，通常只能得到局部解；多次启动或 K-Means++ 改善初始化，不保证找到全局最优。

特征标准化是否合适取决于单位和业务含义。尺度差异可能主导距离，但不能把“所有数据都必须标准化”当作算法要求。

### 复杂度与边界

- 朴素 T 轮迭代时间约 O(Tnkd)。
- 若广播构造 `n × k × d` 差值张量，临时空间可达 O(nkd)；分块或不同距离计算方式会改变内存成本。
- 检查非空二维输入、有限值、1 ≤ k ≤ n、max_iter ≥ 1、非负 tol；重复点也可能导致空簇。
- 空簇保留旧中心只是政策之一，也可重新初始化；必须说明规则，不能保证最终一定有 k 个非空簇。
- 停止时要说明返回的中心与标签是否对应同一轮，以及是否执行最后一次标签分配。

**原示例的静态审查：** tol 满足时先 break、后面的 `centers = new_centers` 不执行，因此返回的是旧中心；如果迭代上限耗尽，中心已更新，但标签仍可能来自更新前的中心。根据接口契约，可先接收新中心并在返回前重新分配标签。本次只读控制流，未执行反例；也不能因为一处顺序问题就宣称整个方法无效。

**一手核验：** [scikit-learn KMeans 文档](https://scikit-learn.org/stable/modules/generated/sklearn.cluster.KMeans.html)讨论局部最小、多次初始化、提前停止时中心/标签的一致性，并说明最后重新分配标签以匹配 predict。

**待练习：** 两个明显分离的小簇、固定随机种子、空簇、重复点、k=1、k=n、tol 提前停止和迭代次数耗尽。比较聚类结果时考虑簇编号置换，不能仅按标签数字逐位比较。

## 4. Adam：矩估计、偏差修正与状态生命周期

**作者来源：** [Adam 展开帖](https://x.com/Zen_with_AI/status/2114772800280146217)。作者介绍一阶/二阶矩的指数移动平均、零初始化偏差修正，以及 Adam 与 AdamW 的区别。

### 输入、输出与机制

输入包括参数 θ、当前梯度 g、历史状态 m/v、步数 t 及超参数。每一步更新状态和参数：

- `m_t = beta1 * m_(t-1) + (1-beta1) * g_t`
- `v_t = beta2 * v_(t-1) + (1-beta2) * g_t²`
- `m_hat = m_t / (1-beta1^t)`，`v_hat = v_t / (1-beta2^t)`
- `theta_t = theta_(t-1) - lr * m_hat / (sqrt(v_hat) + eps)`

零初始化会使早期矩估计偏向零，修正项用于补偿这一点。t 从 1 开始，连续训练或恢复时不能随意重置。v 是梯度平方的二阶原始矩估计，不应直接称为中心化方差。

原论文给出的常用默认值为 lr=0.001、beta1=0.9、beta2=0.999、eps=1e-8，不是对所有模型和精度都最优的参数。

### 复杂度与边界

- P 个参数的一步更新为 O(P) 时间，两份矩状态为 O(P) 空间；它们不是完整训练显存，还存在参数、梯度、激活及可能的其他状态。
- 每个参数需要正确对应自己的状态。通过 zip 遍历参数和梯度时，数量不匹配可能静默截断；应检查数量、形状、dtype 和缺失梯度政策。
- AdamW 将权重衰减与自适应梯度更新解耦，不等于在 Adam 的梯度中直接加入 L2 项。
- 教学更新式不等价于完整训练框架：混合精度、梯度缩放、稀疏梯度、状态保存/恢复等需要额外设计。

**一手核验：** [Adam 原论文 Algorithm 1](https://arxiv.org/pdf/1412.6980)给出更新与偏差修正；[Decoupled Weight Decay Regularization](https://arxiv.org/abs/1711.05101)解释自适应优化下 L2 正则与解耦权重衰减的差异。

**待练习：** 手算首步及连续两步、零梯度、多参数独立状态、保存后恢复步数；与参考实现对拍时对齐 eps 位置、dtype、weight decay 和其他选项。本次未运行这些测试，未实现 AdamW。

## 5. Beam Search：有限候选搜索不等于全局最优

**作者来源：** [Beam Search 展开帖](https://x.com/Zen_with_AI/status/2114772800980566379)。作者展示候选扩展、累计对数概率、保留 top-B、EOS 完成集合与长度归一化。

### 输入、输出与机制

输入为起始序列、提供下一 token 分数的模型或函数、beam 宽度 B、词表、EOS 和长度上限。每轮扩展活跃候选，累加 token 的 log-probability，再保留部分候选继续搜索；已结束序列进入完成集合而不再扩展。

对数求和避免许多小概率连乘的下溢。长度归一化改变排序目标，可缓解偏好短序列的问题，但采用何种长度、是否包含 BOS/提示词、何时归一化都必须定义。原示例用整条序列长度，包含起始 token，不应默认为只计算新生成 token。

有限宽度会丢弃路径，因此不保证全局最优；更大的 B 也不保证文本质量更高。在此确定性、每步取最高分的算法中 B=1 对应贪心；不能将它推广成任意开启 sampling 的框架配置。

### 复杂度与边界

- 每步约考察 B×V 个扩展，但完整成本还包括模型计算、top-B 选择、序列复制和状态管理。
- 原 Python 示例物化所有候选，并用 `seq + [token]` 复制序列。长度约 L 时，临时候选存储可达 O(BVL)，不能将保留 B 条序列的 O(BL) 写成整个实现的峰值空间。
- 同理，“O(LBV) 时间”只能作为忽略部分成本的候选访问量级，不能覆盖该代码中的堆选择、随长度增长的复制及模型推理。
- 达到 B 条完成候选就停止，是一种停止政策，不是最终长度归一化目标下“剩余活跃路径不可能更好”的证明。
- 原示例最终把尚未结束的 beams 也加入返回候选，结果可能不含 EOS。需要明确这是接受截断结果还是应报告未完成。
- 检查 B ≥ 1、长度上限、空词表、非法分数、起始/EOS token 规则及无可扩展路径。

以上是对教学代码的静态分析，不是运行测量。

**一手核验：** [Hugging Face 文本生成配置](https://huggingface.co/docs/transformers/main_classes/text_generation)区分 early_stopping 的不同规则，并说明 length_penalty 的作用。框架示例中的生成 token 长度不包含提示词；使用时应核对所选接口，而不是直接套用教学示例的 len(seq)。

**待练习：** 用极小的、完全可枚举的 token 转移表作 oracle，比较贪心、有限 beam 与穷举最优；构造早 EOS、无 EOS、长度归一化改变名次和较早完成却不是最优的例子。先定义目标再比较，不把不同评分函数的结果当作同一算法的对错。

## 如何使用这张卡

建议按“讲清楚 → 手算 → 最小实现 → 反例 → 对照资料”循环，每次只选一个算法。

1. **讲契约：** 输入、输出、维度、非法值和成功标准是什么？
2. **讲机制：** 为什么这样更新或选择？关键不变量是什么？
3. **写最小实现：** 不先追求工程功能齐全，也不靠背一整段截图。
4. **设计验证：** 手算小例子、独立枚举、性质测试或官方实现对照；每种 oracle 也有自己的前提。
5. **解释差异：** 教学实现缺了哪些 batch、精度、内存、恢复或停止规则？哪些是当前岗位真正需要的？
6. **记录实证：** 用[练习与证据模板](../practice/evidence-and-study-log.md)保存自己的运行环境、预期、实际结果和未验证范围。不要将本卡的静态审查写成自己已经完成的实验。
