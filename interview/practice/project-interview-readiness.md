# 从会讲项目到能胜任：自测与补强路径

这份清单对照优秀候选人的可观察行为，不给某个人贴“不会”的标签。公开资料没写，不等于没有能力；答案写出来，也不等于已经掌握。没有具体 JD、职级和面试评分表，不能承诺“满分”。

主线为测试开发、Python 工具工程与后端工程，AI 应用作为扩展。配合[目标回答](../topics/project-depth-and-tradeoffs.md#interviewer-three-questions)与[证据卡](public-project-interview-evidence.md)使用。

## 先区分三种差距

- **项目证据已有：** 公开资料能支持设计或实现存在，可据此准备讲解；仍须能解释与演示。
- **个人掌握待核实：** 是否能独立推导、复现、定位，是否确有本人决策记录，公开资料无法代答。这是待自测项，不是判定能力不足。
- **项目能力/练习待补：** 现有公开实现明确未覆盖，或本轮尚未执行的练习。可以通过实验或设计推演补强，但不冒充已有生产经验。

建议每项只标“能独立完成 / 需提示完成 / 尚未验证”，记录证据，不累加分数预测录用。

## 核心能力对照

| 能力 | 优秀候选人的目标表现 | 已有公开材料支持 | 需要自己补的证据 |
| --- | --- | --- | --- |
| 架构与边界 | 画清数据/控制流、状态归属、失败路径与不做事项 | XAT 生命周期和文件进程；通知网关的路由及结果分类 | 脱离笔记讲清一条正常和两条失败链路 |
| Python 机制 | 能从语言语义推导框架行为，给最小反例 | XAT 复制、缓存、对象协议及资源生命周期 | 独立复现准备阶段失败、别名污染或缓存失效 |
| 并发与隔离 | 区分线程/进程/外部资源，解释一致性边界 | 文件进程、进程内限流、本地 JSON 读改写 | 可控交错实验和替代方案论证 |
| 测试可信度 | 期望独立于实现；修复前失败、修复后通过；错误分类准确 | 公开 XAT 错误总价示例；通知 partial 测试 | 亲自解释断言、植入缺陷、保留实际输出 |
| 主动推动 | 从问题选择到验证与停止条件，不只执行任务 | XAT 公开职责与可迁移目标；研究工具分阶段范围 | 一个确有记录的本人决策，不虚构协作或收益 |
| 复杂问题诊断 | 对比假设，以证据排除原因，保留恢复与复盘 | 三个项目提供可分析的边界 | 一个本人真实问题过程；没有则先完成独立实验 |
| 交付与演进 | 兼容、迁移、故障恢复、观测和成本均有边界 | XAT 公开安装验证报告；网关替换引擎的接口边界 | 可复现交付检查、升级条件、回退方案和量测 |

## 六个练习，按能力依赖推进

每个练习都在可丢弃环境或独立最小示例中完成，不修改公司系统、不发真实通知、不使用秘密或真实业务数据。没有原项目运行权限时，用标准库小实验检验机制；它只能证明机制理解，不能算原项目验收。以下均是计划，不是已完成记录。

### 练习 1：架构与失败时序，建议 45—60 分钟

选择一个最熟悉项目，画入口、校验、执行、依赖、结果、清理六部分。标记哪些状态在进程内，哪些在外部系统，谁拥有资源。

**验收：** 不看笔记讲 90 秒；随后给出正常、准备失败、依赖超时或执行器异常三条时序。每条至少说明可观察结果和恢复边界。别人把一个组件替换掉时，能指出受影响契约，不只是重新背图。

**产物：** 一页架构与三条时序；去掉未公开地址、实体名和生产数字。

### 练习 2：生命周期与 Python 语义，建议两次各 45 分钟

先用 unittest 最小实验取得模拟资源并登记清理，再让 setUp 后半段失败；观察测试主体、tearDown 与 cleanup 各是否执行。另做嵌套可变对象浅拷贝/深拷贝对照，以及缓存结果被调用方修改的反例。

**验收：** 先写预测，记录实际顺序及错误分类；资源清理断言独立于打印日志；能解释强制终止不受同样保证。第二部分能指出共享的是哪一个对象，而非只背“深拷贝更安全”。

**产物：** 最小脚本、运行环境、命令与实际结果。参考[Python 官方 unittest 清理说明](https://docs.python.org/3.12/library/unittest.html#unittest.TestCase.addCleanup)和[copy 文档](https://docs.python.org/3.12/library/copy.html)。

### 练习 3：证明测试真的能发现错误，建议 60—90 分钟

选择通知结果分类或一个简单业务计算，先写规则矩阵和独立 expected，再运行正常实现。分别植入“partial 被当成 sent”“删掉一条关键断言”或“错误总价仍成功”的有限缺陷，观察测试。

**验收：** 至少两种代表性错误触发目标断言失败；确认不是导入失败或环境错误。恢复后通过。若删除断言仍绿，明确指出哪个风险没有被检查，并补上能暴露该风险的测试。

**产物：** 规则—用例—缺陷映射、修复前后结果及未覆盖范围。不把少量人工缺陷实验称为完整变异测试或生产检出率。

### 练习 4：确定性并发反例，建议 90 分钟

使用两个受控写入者，在独立临时目录复现读同一旧快照后分别写入的情况；通过事件或屏障控制交错，不靠重复 sleep 碰运气。或者用两个进程说明各自内存限流并非一个全局配额。

**验收：** 错误方案稳定违反同一不变量，正确方案在目标作用域内保留预期状态。检查顺序路径、失败路径及清理。若使用单进程锁，明确它不能证明跨进程正确；若更换临时文件名，仍检查丢失更新是否存在。

**产物：** 交错图、旧/新结果、修复适用范围。源码风险分析与实验确认分开记录。

### 练习 5：有成本的设计选择，建议 90 分钟

对测试执行模型比较串行、线程或进程中的两个可实现方案，或为通知服务比较同步响应与持久队列。先定义一致的输入、正确性与故障标准，再选择指标。

**验收：** 至少两种负载分布，重复运行并记录波动；报告总耗时、长尾、资源峰值及失败，注明环境和数据规模。没有性能改进也如实报告。若只做设计评审，不填写虚构基准值。

**产物：** 一页决策记录：约束、候选、证据、选择、代价、反转条件。资深岗位还要补扩容触发条件、迁移/回滚与维护责任；练习不等于承担过生产责任。

### 练习 6：主动学习与复杂问题双故事，建议 45 分钟

从真实记录选一个学习决策和一个困难问题。各写“触发 → 备选 → 本人动作 → 证据 → 改变的判断 → 残余风险”，准备 90 秒与 5 分钟两种长度。

**验收：** 每个第一人称动作能对应实际记录；能回答“为什么不是其他方案”和“若结果相反会怎么办”；他人的贡献与 AI 参与明确。没有历史证据时，用本轮新实验讲当下学习，不把它追溯成过去事故。

**产物：** 公开版只留通用技术与已公开项目。私下口述也遵守保密约定，不披露公司或个人无关信息。

## 怎样安排优先级

先做 1 和 2，确保能解释；再做 3 和 4，确保能验证；最后做 5 和 6，形成可深入的决策故事。时间估计只是练习预算，不是自动安排日程或学习完成承诺。每轮只补一个最薄弱环节，并在[证据日志](evidence-and-study-log.md)记下真实结果。

若目标偏资深，另检查是否有真实的跨模块约束、容量规划、迁移与回滚、故障协同及长期维护证据。能提出这些方案是设计能力，实际承担过责任是经验，两者都值得展示但不可互换。若目标偏 AI 应用，再补基于公开样例的检索/引用正确性、拒答和工具权限评测；不要只因项目名含 AI 就推定已经具备这些证据。
